5. Projection System — How Stokastic Builds It (Verified + Reproducible)

Official description: “The projection system is not a rating built off last season's box scores. It runs high-level simulations, many times over, before each contest to settle on the most fine-tuned number for a player.” verified

Also: “the Sims simulate every game play by play with QB-to-pass-catcher correlation baked in… run the Contest Sims, which play every lineup in your pool against all the others… across tens of thousands of simulated contests” verified (an earlier “millions of data points” marketing claim lived on a page that now redirects — flagged, re-sourced to live copy).

7. Simulation Engine — Contest-Level (The Core Differentiator)

Verified: “Game level simulation tools exist on the market currently to help users with projecting player performance. However, nowhere else do users have the ability to perform simulations on the contest level, helping you find the edge in real tournaments.” verified

Verified workflow: “A DFS Sim is an advanced simulation tool that tests lineups in realistic tournament models… Import lineups through our contest generator, or by uploading a .csv file containing lineups and pit them against each other in a lifelike slate simulation.” verified — plus “play every lineup in your pool against all the others, at your chosen field size and percent-to-first, across tens of thousands of simulated contests… The output is a simulated ROI for every lineup” verified

Steps to Rebuild (Open Source)

  1. Player Distributions: For each player, have median + stddev + ceiling/floor from historical. Not independent — use correlation matrix (e.g., QB-WR 0.6, WR-WR same team 0.3, QB-opp WR -0.1)
  2. Monte Carlo Slate Sims: Run N=10,000+ slates. Each sim draws each player from his distribution with correlation via Cholesky decomposition.
  3. Field Simulation: Generate field lineups using projected ownership as sampling weights. Field size = actual contest entries.
  4. Lineup vs Field: For each user lineup, compute fantasy score per sim, rank vs field, assign payout per contest payout structure, compute ROI = (avg payout - entry)/entry
  5. Output: Sim ROI%, Cash Rate%, Win%, Optimal Rate%, Leverage Score

Code: src/projection_engine/simulation_engine.py implements this with numpy.

Why It Beats Optimizer (Verified)

“Most DFS tools are optimizers. You feed in projections, optimizer solves for highest-projected lineup under salary cap, and you get median answer to a question that tournaments never ask. A Milly Maker does not pay median lineup. It pays lineup that beats field of hundreds of thousands once” verified

12. Limitations & Next Session Work

Current Limitations (Honest)

  • Historical ownership data: Stokastic's ownership accuracy comes from years of private contest data. We proxy with optimal% + salary. To match quality, need to buy or crowdsource historical ownership.
  • Real-time news pipeline: Stokastic has live injury feed. Our open version polls NBA.com injury report + Twitter beat writers. Needs WebSocket for <1min latency.
  • Correlation matrix: True correlations require play-by-play joint distributions. We use industry heuristics (0.6 QB-WR). Next: compute from nflverse / pbpstats.
  • Statcast rate limits: Baseball Savant blocks aggressive scraping. Need official MLB Stats API key or SportsGameOdds feed.
  • No paid data: Stokastic ships proprietary simulation + correlation machinery. We only use free tiers. For same quality, need Cleaning the Glass, PFF, or SportsInfoSolutions subscription.
  • Contest payout structures: DK/FD payout curves change weekly. Need scraper for contest lobby.
  • Legal: Cannot copy Stokastic's proprietary code. Only reverse engineer methodology from public statements — which we did.
